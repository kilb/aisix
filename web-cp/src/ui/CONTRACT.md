# Design-system component contract

The Dashboard (`web-cp/src/ui`) and the tenant portal (`web-tenant/src/ui`) each build their own copy of the design system (ruling P2c-R4), with one contract. These files are byte-equal in the two apps, and `web-tenant/src/lib/tokenParity.test.ts` fails when they drift: `theme/tokens.css`, `theme/base.css`, this file, and `Button`, `Field`, `Toast`, `TwoStep`, `Lamp`, `EmptyState`, `DataTable` and `Icon` (`.tsx`). Change a shared file in both apps in the same commit. Each app's `ui/ui.css` styles these components with the same class names and the same look. Only the layout around them differs: in the Dashboard a note carries its own margin, while the portal spaces its panels' children by gap. Every asserted text, role and label in the Playwright specs wins over anything here.

**Button** (`Button.tsx`). Props: `kind` is `primary` (a Sign-yellow fill with Ink text, one per view), `secondary` (an Ink outline, the default), `danger` (the Stop-red fill, for the second step of a destructive action only) or `quiet` (a text button for headers and dense rows). `size="sm"` is 32px, and the default is 36px. `block` fills the container. `icon` names an icon before the label; with no children and an `aria-label`, it is an icon-only button. `type` defaults to `button`, so a submit states `type="submit"`. States: hover, pressed, focus ring and disabled at 45%. `busy` disables the button (a second click cannot send the request again) and puts a spinner in the label's place at the same width. `disabledReason` explains a disabled button whose reason is not on screen. Accessibility: while `busy`, the accessible name is `busyLabel` (default `处理中…`); pass the wording the button had before, such as `保存中…`. With `disabledReason`, the button stays focusable (`aria-disabled="true"`, and a click does nothing), so the reason shows in a `role="tooltip"` on hover and on keyboard focus and is joined to the button's `aria-describedby`.

**Field** (`Field.tsx`). Props: `label`, `hint` (optional, shown under the control), `error` (the refusal, in the error red under the hint), `wide` (spans both columns of a two-column form), and `children`. `children` is the control, or a function `(aria) => control` whose attributes you spread on the control. A control with a hint or a refusal must use the function form. States: a refused control has `aria-invalid` and an error-red edge. Accessibility: the label wraps the control, so the accessible name is the label alone. `aria-describedby` names the hint, then the refusal; the ids come from `useId`, so the caller wires none. The refusal (`p.field-problem`) has no role, so a screen reader hears it with the control. A refused submit therefore moves the focus to that control: every form that shows field refusals takes `const [form, focusRefusal] = useRefusalFocus()` from `Field.tsx`, puts `ref={form}` on the form (or on the part of the page that holds its fields), and calls `focusRefusal()` whenever a submit comes back with field refusals, from the server or from its own checks. Once they render, focus moves to the first `aria-invalid="true"` control in document order (a refused fieldset passes it to its first control), so a screen reader reads that field's label and its refusal. A refusal that names no field stays in the form's own `.note.crit` with `role="alert"`, which is announced as before; when no field was refused, the focus stays where it was.

**Toast** (`Toast.tsx`). `ToastProvider` wraps the app, and `useToast()` returns `toast(text, { announce? })`. Word the text with the action's own verb (保存 → 已保存). A toast appears bottom left, slides up 8px and fades in over 160ms, stays three seconds, then fades out over 200ms. At most three show at once. Accessibility: the stack is a polite live region with no role, so it never competes with a page's `status` or `alert`. A toast is announced by default. Pass `announce: false` only when the page already says the same words in a live status of its own, as the portal's shown-once secret does. Never let a toast be the only place a message appears.

**TwoStep** (`TwoStep.tsx`; the portal's `ConfirmButton` is a deprecated alias). Props: `label`, `onConfirm`, `disabled`, `kind` (`primary` or `secondary`, for the first step only), `size="sm"`, `ask` (decides at each first click whether to ask at all; when it returns false, the first click acts), and `warning`. States: the first click swaps the button in place for `确认<label>` in Stop red and `取消`, with the warning on a line under them. The swap fades in while the box eases to its new width over 120ms, and reduced motion skips the motion. Accessibility: keep the labels exactly `确认<label>` and `取消`. Focus that was on the step moves to `取消` when it opens, so a second Enter takes it back and does not act, and returns to the action when it closes. Escape takes the step back without closing the panel around it. The warning is a `role="alert"`, so it is heard as the step opens.

**Lamp** (`Lamp.tsx`). Props: `state` is `applied` (green), `propagating` (blue, pulses once), `pending` (hollow), `rejected` (red) or `disabled` (grey); `children` is the word; `title` is optional. Accessibility: never colour alone, since the word is the text and the dot is drawn by CSS. The state is in `data-lamp`, never `data-state`, which the Dashboard's specs read for the rollout badge.

**EmptyState** (`EmptyState.tsx`). Props: `text` is one sentence on what to do next; `mark` is the 32px mark (default `route`); `action` is the one button that starts it. Leave `action` out when the page already shows a button of that name, because the specs find buttons by name in strict mode.

**DataTable and Loading** (`DataTable.tsx`). `DataTable` props: `label` (the table's accessible name), `compact` (36px rows), `scroll` (a vertical scroll area of its own, so the sticky header stays in view), and `children` (its `thead` and `tbody`). Rows are 44px, or 56px with a `.cell-note` line. They hover in Concrete and have no zebra stripes, and the table scrolls sideways inside its own box on a narrow screen. Cell classes: `num` for right-aligned tabular numbers (on the cell and its header), `right` for a row's actions, and `tabular` for tabular figures that stay left-aligned (dates, mixed limits). `Loading` is three skeleton rows plus the `载入中…` status text, which is visually hidden but stays in the DOM for assistive technology and the specs.

**Icon and Mark** (`Icon.tsx`). `Icon` draws a 16px icon with a 1.5px round stroke; `Mark` draws a 32px empty-state mark. Both are inline SVG in `currentColor`, with no icon library. Use icons sparingly: on actions such as refresh, copy, close, external and the theme switch, and never on navigation stops. Accessibility: always decorative (`aria-hidden`); the control carries the words.

**Notes and classes** (`ui.css`, `base.css`). A `.note` is a passage in a panel with a 3px bar on its left: grey by default, `.ok` green, `.warn` Sign yellow and `.crit` Stop red. The text stays in the text colour. A note that reports a refusal or a failure has `role="alert"`, and a success has `role="status"`. Shared classes: `.tag` (a 20px chip, such as a role), `.hint` (secondary text), `.field-problem` (a refusal), `.cell-note` (the second line in a cell), `.trunc` (one line with an ellipsis, width from `--trunc`, default 200px, with the full text in `title`), `.vh` (visually hidden), `.display` (Latin-only 800 display text), `.cur` and `.unit` (a muted currency sign or unit beside a figure), and `.money`, `.num` and `.tabular` (tabular figures). Each app has its own route nav: a vertical rail in the Dashboard and a top bar in the portal. Both share one keyboard model: a `tablist` with roving tabindex, arrows, Home and End to move focus, and Enter or Space to open. Each also has its own extras: `CopyButton`, `SidePanel` and `GroupName` in the Dashboard, and `ThemeToggle` and `ShownOnce` in the portal.
