# 上游统计口径修正（用户澄清，2026-11-14）

用户原话：

> 我说的字节量是指发送给llm的字节量及llm输出的字节量，本质是为了估算上游返回的token用量是否正确

以下修正覆盖本文后续的 `client_exchange` 设计。后续旧设计保留为过程记录，不能继续用作验收合同。当前客户端边界的代码和既有验证尚不满足这次澄清；不能将旧测试通过数视为本功能完成。

## 采集边界

- 一组统计属于一次真实上游尝试，并与该次用量事件关联。采集最终发往上游的请求，位于护栏、协议桥接、模型名及提供方参数处理之后；采集上游原始输出，位于客户端渲染、改写、过滤之前。
- 请求/响应正文大小与可解码的模型输入/输出文本长度分开记录。正文可包含 JSON、SSE 和媒体包装，不能直接视为模型文本 Token。应用层正文大小不包含 HTTP 头、TLS 或网络重传；解压后的响应大小不能标成压缩后的网络流量。
- 文本参考须覆盖实际发送的上下文和可观测的工具输入，明确工具定义、结构描述、媒体、远程文件、托管上下文、隐藏推理等计数是否覆盖。无法观测或不能完整解析的部分保持未知或标为部分，不能用客户端原文替代，也不能伪造零。
- 流式输出按上游实际收到的内容累计，去重 delta、done 和终态快照中的重复载体。终态或中断时固定快照；客户端传输进度不决定该快照。
- 重试分别归属各自 attempt；并行成员不能共享“最新响应”计数。缓存命中及未派发请求不产生虚构的上游字节；异步受理、管理查询与实际推理终态不可混计。

## 上报与核验

- 保持原有用量事件发布时间、Token、价格及计费次数；在原事件中附带该次上游长度快照，不为长度等待客户端正文结束，不以客户端交付补注替代上游统计。
- 中断时只能报告已观察到的前缀，并标记不完整；缺少终态不能宣称已知上游的完整生成量。最终用量与可见文本可能因隐藏推理、媒体或托管上下文而不可直接比较，界面须说明限制。
- 新口径使用明确区分的边界/版本。历史 `client_exchange` 只作为客户端统计展示，不能重标成上游统计；旧元数据补注不能覆盖新的上游快照。
- 控制面展示上游请求/响应正文大小、输入/输出文本长度、完整性、对应的记录用量及估算方法。UTF-8 字节除以 4 仅作为未校准参考，不以偏差单独判定用量造假，不影响计费。

## 必须重新验证

1. 用真实路由和可检查收到请求的上游组件验证：护栏/协议变换后内容改变，统计必须跟随上游实际内容；输出被客户端侧改写时，上游统计保持原值。
2. 验证流式/非流式、重试、并发成员、首内容前错误、取消、缓存命中、零与未知、管理交换和异步终态的归属；不能仅覆盖 Chat。
3. 实际控制面接收、存储、查询和真实后端 Playwright 展示新边界；验证旧边界不会误标，旧补注无法覆盖新快照，计价完全不变。
4. 原先四条客户端正文完成时机测试不能作为此次上游需求的验收；应由上述上游边界用例取代。其他未获批准的测试更改不在本次澄清授权内。

# 输入输出字节与 Token 参考核验

用户原话：记录输入输出的字节数，控制面能够根据字数估算 Token 数，从而核验返回的 Token 计数是否与预期一致。用户要求直接执行、独立任务并行；以下实现选择由执行者负责，并非声称用户已逐项确认。模型能力匹配工具按用户指定顺序放在本版本部署之后。

## 实现选择

采用客户端交换边界：分别记录 HTTP body 字节和已观测模型文本 UTF-8 字节、Unicode scalar 数。两种长度不可混称。对文本计算 `ceil(utf8_bytes / 4)` 未校准参考，与原有用量并列展示，明确客户端边界、来源和覆盖限制。它不修改 Token、计费、配额、价格或历史数据，不自动判定上游多收费。

只测 body 会把 JSON 转义、SSE 包装和二进制当成文本；仅测文本不能满足流量诊断。逐供应商实际输入的逐次计量更适合精确审计，但涉及所有桥接器、云 SDK、隐藏上下文，不能将当前客户端参考伪装为这类测量。三网关及官方 SDK 比较见私有证据 `token-audit-v8/reports/token核验设计.md`；公开说明只描述方法。

## 事件合同

UsageEvent 新增可选 `io_audit`，旧记录缺失保持未知，真实零必须保留。共享类型置于 aisix-core::usage_io，以便 DP/CP 共用验证规则：

```text
UsageIoAudit {
  version: 1,
  boundary: "client_exchange",
  request_body_bytes: Option<u64>,
  response_body_bytes: Option<u64>,
  response_complete: bool,
  input_text: Option<TextMeasurement>,
  output_text: Option<TextMeasurement>,
}
TextMeasurement {
  utf8_bytes: u64,
  unicode_scalars: u64,
  complete: bool,
}
```

只把一次客户端交换的观察附在 HTTP 终态行；重试中间行不可复制同一组数据。原用量行按既有时点立即结算，最终长度在正文结束后通过独立的有界队列发送元数据补充，不能延迟计费或占用账单队列容量。补充使用既有 mTLS 传输与重试，独立传输状态不影响账单健康、计数或出口。补充只携带 `kind: io_audit_update`、既有 event_id 和 io_audit，不携带或改写 Token、价格、错误和身份。CP 在同一来源 DP 的既有行上合并该字段；补充先到时以持久暂存处理，重放不重复计价。旧 CP 无此补充协议，因此部署顺序为 CP 在先，新 DP 在后。accepted 后台行可带受理交换体积，后台推理终态没有直接 HTTP 交换，保持未知；轮询结果不冒充新生成。WS 单轮可带逻辑文本参考，HTTP body 两字段为空，绝不把内部合成 POST/SSE 字节当 WS 流量。握手本身没有模型文本。

`request_body_bytes` 复用最外层计数：只在正文完整读入且未丢弃时存在。压缩请求表示压缩后的应用 body。`response_body_bytes` 表示交给 HTTP server 的 data-frame 字节，含 SSE 包装，不含 headers/TLS；不证明客户端收到。流中断保留已交出前缀并令 response_complete=false。请求/响应精确 body 大小只能在正文结束或 drop 后附加，不能在 handler 提前快照。

文本按协议已解码的文字/可见推理/拒绝文字/工具参数计数；涵盖所有实际交付 choices。输入边界为客户端原始已解码文本，位于输入护栏重写及供应商变换之前；输出位于客户端可见的最终护栏重写之后。输入含明确的 prose、system、历史消息与工具结果；工具定义、schema、媒体、远端文件、stored context 和 framing 不在参考范围。已知空文本为零；未支持的协议、二进制或不完整解码为空或 complete=false，不能伪造零。Responses 的 delta/done/terminal 快照只能采用一次，取消标明前缀。观察器独立于内容 capture 开关与截断，不能保存完整提示或回答。

Chat、Completions、Messages/count_tokens、Responses HTTP/WS 的文本槽必须有明确接线；embeddings/rerank/audio/images 等可观测文字输入输出也按相同规则采集。文件/批次等管理交换只带 body 大小。工具/schema/多模态/存储上下文/隐藏推理的限制作为固定说明展示，不引入未经校准的准确率或阈值配置。

## 展示与验证

控制面和租户调用详情展示 body 大小、输入/输出文本字节和字符数、粗略参考、完整/部分/未知状态。原计数统一称已记录用量；`usage_estimated=true` 显示包含网关估算，false/缺失也不能证明每个方向由上游明确报告（零和缺失可能有历史歧义），不可一律标成上游报告。输入对照使用现有共享缓存投影：subset 缓存不相加，additive 缓存相加。输出不假设 completion-reasoning 等于可见 Token。历史字段缺失显示不可用。

验收必须能因删除字段/改为零/重复累计而失败：`A汉😀` 为 8 bytes/3 scalars，JSON 转义等价；零与未知；所有文本协议和流式重复载体；压缩/body framing；取消/未 poll body/重试终态只一次；capture 关闭/大文本内存；CP 实际 intake/查询与 Playwright；附加审计前后价格完全相同。用量及时发布且仅一次；补充先后到达、并发、重放及跨 DP 均不改变账单。Root 独占 Cargo，已有内存与计费断言保持不变。063 实际运行证明整体延迟用量事件会令现有消费者挂起，因此已撤销该实现；四条新写的错误发布时间断言待用户按项目第 5 节确认修正，其余原有测试不得放宽。完成后冷审计并按既定 CP-first 并行网关切换计划部署，保留活动连接。
